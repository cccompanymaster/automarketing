# 보안 구성 요약

마지막 점검: 2026-11-08

## 데이터베이스 (Supabase)
- **모든 테이블 RLS 사용.** 비회원(anon)은 상품 단가표(`catalog_items`)만 읽을 수 있음.
- **회원은 자기 데이터만 읽기**: 주문·캐시 내역·산출물·충전 신청·동의 기록. 쓰기는 전부 서버 함수(RPC)로만 가능하고, 함수 안에서 `auth.uid()`로 본인 확인.
- **관리자 판별(`is_admin`)**: 로그인한 계정 자체를 `admin_users` 목록과 대조하고, 이메일 인증이 끝난 계정만 인정. 토큰에 이메일만 바꿔 넣는 방식으로는 관리자가 될 수 없음.
- **주문 계정 비밀번호(서로이웃·이웃 추가)**: Supabase Vault에 암호화 저장. 관리자 함수로만 열람, 주문이 완료·취소되면 즉시 삭제. 주문 내용·메일·임시 저장에는 남지 않음.
- **상품 실비**: 관리자 전용 테이블(`product_costs`). 사이트 코드에는 들어가지 않음.
- **주문 첨부 파일**: 비공개 버킷 `order-files`. 본인 폴더에만 올릴 수 있고, 열람은 본인·관리자만(10분짜리 서명 링크).
- **가격**: 서버가 단가표로 다시 계산(`place_order`). 화면 금액을 조작해도 결제 금액은 바뀌지 않음. 같은 주문 키로 두 번 눌러도 한 번만 결제.

## 사이트
- Content-Security-Policy를 `<meta>`로 적용(`src/lib/csp.ts`). 허용한 외부 출처만 스크립트·연결 가능.
- 관리자·마이페이지는 검색 색인 제외(noindex).

## 사장님이 대시보드에서 켜 둘 것
- Supabase → Authentication → **Leaked password protection**(유출 비밀번호 차단) 켜기.
- 관리자 계정 **2단계 인증(MFA)** — Supabase 대시보드 계정과 사이트 관리자 계정 모두.
- Supabase **개인 액세스 토큰**은 쓰고 나면 삭제.

## 알고도 둔 것
- `pg_net` 확장이 public 스키마에 있음(Supabase 경고). 옮기려면 확장을 지웠다 다시 만들어야 해서, 그 사이 입금·문의 알림이 끊길 수 있어 두었음. 기능상 위험은 없음.
- 비회원이 부를 수 있는 함수(`submit_inquiry`, 계산기 댓글)는 설계상 공개. 연락처당 10분 5회 제한·허니팟 등으로 남용 방지.
